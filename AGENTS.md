# Contributor rules

These apply to everyone, human or agent.

## Code

- Keep it simple and minimal. Every file, function and option must have a clear reason to exist.
- Don't add abstractions, flags or config for needs nobody has yet.

## Tests

- Cover the cases that matter most: the main path and the failures that would hurt users.
- Don't test every permutation.

## Writing (comments, commit messages, PR titles and descriptions, issues)

- No em-dashes.
- No AI tells: no filler, hype, hedging, emphasis in caps, or phrases like "robust", "seamless", "comprehensive", "it's worth noting", "delve".
- Be plain and short. Say the point first. Use bullet points where they help.
- No Claude or AI attribution anywhere: no `Co-Authored-By` trailers, "Generated with" footers or session links.
